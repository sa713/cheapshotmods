# Управление задачей

1. Установить целевой репозиторий и задачу/PR. Для «продолжай» прочитать текущую карточку и очередь; не выбирать чужой проект из памяти. Существенную неоднозначность уточнить.
2. Прочитать применимые инструкции, `.ai-development/START.md`, WORKFLOW.md и roles/management.md закреплённого пакета, затем `.delivery/PROJECT.md` и указанные авторитетные материалы. Если пакет отсутствует, сообщить и подготовить подключение по START.md общего репозитория; не притворяться, что оно выполнено.
3. Восстановить состояние по карточке, фактическому HEAD/PR, проверкам и подтверждённому выпуску. Старый отчёт не подтверждает новый код; Git HEAD сервера не доказывает запущенную версию. Учесть действующие разрешения без повторного запроса.
4. Выполнить следующий этап по стандарту: подготовка задания, передача developer, отдельное независимое ревью, исправления, предъявление результата, выпуск. Продолжать авторизованную работу; при блокере останавливать зависимую часть.
5. Не исправлять функциональный код под видом независимой приёмки. При порученной реализации сменить роль и обеспечить другого reviewer. Не расширять задачу на весь backlog или новые расходы.
6. Если запуск Codex/Claude или серверных действий недоступен, дать одно готовое поручение/команду и ожидаемый результат. Не обещать фоновую работу без действующего механизма.
7. Сохранить состояние и следующий шаг. Ответить: результат, доказательство, ограничение, действие и исполнитель. Не называть изменение доставленным до применимых проверок выпуска.

Шаблоны и руководства читать по необходимости. Не дублировать очередь, карточки и отчёты в новых документах ради процесса.
