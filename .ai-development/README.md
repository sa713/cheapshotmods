# AI Development — наш стандарт разработки

Рабочий стандарт разработки программных продуктов с помощью ИИ. Версия **1.1.0**. Действует для новых продуктов и для явно подключённых существующих репозиториев. Описывает полный цикл: от идеи до проверенной работы после выпуска и дальнейшего сопровождения. Не предписывает язык, фреймворк, облако или конкретную модель ИИ.

**Это инструкция для владельца продукта. Агентам начинать с [START.md](START.md).**

Для начала достаточно сообщения из раздела «Начать новый продукт». Агент сам читает правила, готовит документы, среду и задачи. Владельцу не требуется вручную заполнять шаблоны или подтверждать промежуточные технические шаги. Уже выданное поручение довести работу до готового результата выполняется до согласованного места доставки; PR служит рабочим инструментом, а не дополнительной обязательной остановкой на одобрение.

## Какие чаты использовать

На продукт создать проект в ChatGPT и два постоянных чата. Репозиторий продукта хранит требования, задачи, решения и состояние. Переписка помогает обсуждать, но не заменяет эти материалы.

| Чат / среда | Что здесь происходит | Что требуется от меня |
| --- | --- | --- |
| **Название · Продукт** — ChatGPT; Work, если нужна запись в GitHub | Идея, сценарии, требования, интерфейс, приоритеты | Объяснять потребность, принимать существенные продуктовые решения |
| **Название · Управление** — ChatGPT Work с GitHub | Техническая подготовка, задания, организация проверки и выпуска, актуальный статус | Принимать решения, которых действительно не хватает |
| **TASK-001 · Разработка** — отдельная задача Codex Cloud | Реализация, тесты, исправления, PR | Запустить готовое поручение, пока автоматический запуск не подключён; результат управляющий читает из GitHub |
| **TASK-001 · Проверка** — новый обычный чат Claude на телефоне | Независимый анализ требований, решений или кода по доступным материалам | Передать подготовленный текст и материалы; вернуть ответ текстом или файлом |

Для маленького продукта продуктовый и управляющий чат можно объединить. Разработчик и независимый проверяющий работают в разных сессиях. Текущий рабочий режим владельца — преимущественно телефон: Claude запускается вручную в обычном чате. Ноутбук и Claude Code для этого не требуются. Проверки с запуском кода выполняются в доступной среде разработки/CI; при необходимости независимого исполнения — в отдельной сессии с такими возможностями. Другой производитель модели не гарантирует отсутствия ошибок.

Названия инструментов — текущая рекомендация. Роли и порядок сохраняются при смене моделей. Параллельные задачи и дополнительные агенты нужны только при явной пользе и технической возможности; они не являются обязательным условием работы.

## Начать новый продукт

Открыть новый проект ChatGPT и чат **«Название · Продукт»**. Скопировать сообщение, дописав идею:

```text
Начинаем новый продукт по стандарту https://github.com/sa713/ai-development.
Прочитай START.md и работай в роли product. Зафиксируй точную версию стандарта.
Моя идея: [описание обычными словами].
Помоги определить пользователей, сценарии и целевой результат. Существенные вопросы
задавай мне, обычные решения предлагай сам. Согласованные требования сохраняй.
Код продукта до подготовки задания не начинай.
```

Если репозиторий уже создан, добавить его ссылку. Если нет — управляющий подготовит создание или попросит создать пустой репозиторий, когда это действительно потребуется. Не нужно заранее придумывать технический стек или самому заполнять шаблоны.

Продуктовый чат должен вернуть согласованное описание и конкретный следующий шаг. Если в режиме Chat нет доступа к записи в GitHub, он готовит один законченный пакет решений для управляющего. Нельзя сообщать «сохранено», когда запись не выполнена.

## Передать продукт в управление

Создать чат **«Название · Управление»** в Work. Скопировать:

```text
Репозиторий продукта: [ссылка]. Ты управляющий разработкой.
Подключи стандарт https://github.com/sa713/ai-development по START.md, если он ещё
не подключён; иначе используй закреплённую в продукте версию .ai-development/START.md.
Прочитай сохранённые требования, проверь реализуемость и подготовь следующую задачу.
Веди состояние в репозитории. Мне возвращай готовые поручения и конкретный следующий шаг.
```

Если продуктовый чат не записал решения, приложить его итоговый пакет. Не пересказывать всю переписку. Управляющий проверяет существующие документы и подключает стандарт, не подменяя согласованные требования шаблонами.

Дальше управляющий сам определяет, что готово к разработке, какие зависимости надо закрыть и какое поручение дать. Выбор модели и усилия он включает в своё сообщение, если это нужно для данной задачи.

Для нового продукта он также готовит и проверяет среду разработки, автоматические проверки, демонстрацию с телефона и способ выпуска по [guides/ENVIRONMENTS.md](guides/ENVIRONMENTS.md). Это часть запуска продукта, которую выполняют агенты. Сохранённые требования читаются из GitHub без повторного переноса между чатами; текущий статус PR и проверок берётся из GitHub, а решения и подтверждения приёмки сохраняются отдельно.

## Запустить разработку

В Codex Cloud выбрать репозиторий продукта и подготовленное окружение. Вставить **готовое поручение управляющего**. Его обычный вид:

```text
Репозиторий: [ссылка]. Роль developer.
Прочитай AGENTS.md и .ai-development/START.md. Выполни TASK-001 из [путь или issue].
Исходная версия и полномочия указаны в задании. Проверь результат и передай PR.
```

Не нужно вручную дописывать длинный список ограничений — он уже находится в правилах и задании. Если задачи TASK-001 нет или она не готова, разработчик должен сообщить это, а не сочинить объём работ.

Разработчик связывает PR с заданием. Управляющий сам находит результат в GitHub; переносить отчёт разработчика не нужно. Если фоновое продолжение ещё не настроено, написать в управление «Продолжай TASK-001». Ссылку на PR требуется передать только если связь с задачей отсутствует или неоднозначна. Исправления по замечаниям обычно продолжать в той же задаче разработки.

## Проверить результат

В управлении написать:

```text
Подготовь TASK-001 к независимой проверке. Для Claude дай готовый текст
и необходимые материалы, которые я смогу передать с телефона.
```

Управляющий находит PR, проверяет фактический HEAD и результаты проверок. Для обычной функциональной задачи он готовит независимое ревью; для небольших правок достаточно соразмерной проверки. Для Claude он возвращает одно готовое сообщение и, если доступ к приватному репозиторию в Claude не подтверждён, один читаемый файл с необходимыми материалами. Владельцу не требуется выбирать файлы, собирать diff, открывать терминал или распаковывать архив. Пример сообщения, которое управляющий заполняет сам:

```text
Независимо оцени [требования / решение / изменения TASK-001].
Проверяемая версия: [полный SHA]; исходные материалы: [ссылки / приложенный файл].
Сначала самостоятельно разберись в задаче и результате. Выбери подход к анализу,
дай аргументированное мнение, доказанные замечания и существенные ограничения.
Отделяй собственный анализ от приложенных результатов чужих проверок.
Если материалы недоступны или их недостаточно, укажи, чего именно не хватает.
Не заявляй о запуске тестов или проверке приложения, если этого не делал.
Верни заключение в чат; не изменяй код или требования.
```

Передать сообщение и материал в новый чат Claude, затем вернуть его ответ в управление текстом или файлом. Ссылки на чат достаточно только при подтверждённой доступности его содержимого управляющему. Состав пакета и порядок работы — [guides/REVIEW_CHAT.md](guides/REVIEW_CHAT.md).

Управляющий сохраняет ответ, разбирает замечания и организует исправления. Анализ кода в обычном чате является самостоятельной частью проверки, но не заменяет запуск тестов и пользовательских сценариев. Обязательные проверки остаются обязательными; при необходимости их независимо выполняет отдельная сессия Codex/Work с доступной средой. Мне предъявляется пользовательский результат: ссылка или артефакт и несколько конкретных действий для оценки.

Автоматический запуск Claude и его GitHub Action сейчас не входят в выбранный маршрут. Запуск Codex и фоновое продолжение управляющего считаются работающими только после отдельной настройки и проверки. До этого управляющий даёт готовое поручение или просит короткое «Продолжай», сохраняя материалы в GitHub.

## Выпустить изменение

После приёмки, когда я решил выпускать, написать в управление:

```text
Разрешаю объединить принятый PR [ссылка] и подготовить выпуск.
Развёртывание — по согласованной политике проекта.
```

Эта фраза сама по себе не разрешает новое платное использование или автоматический доступ к рабочему серверу. Если выпуск выполняю я, управляющий даёт точную команду/скрипт, ожидаемый вывод, способ проверки и восстановления. Я возвращаю результат выполнения.

Если в проекте заранее разрешены слияние и выпуск определённого класса изменений, повторное разрешение перед каждым шагом не нужно. Полномочия записываются в паспорте проекта.

Если в исходном поручении уже явно разрешено довести конкретный результат до main или выпустить его, повторять сообщение о разрешении не требуется. Управляющий сам завершает проверки, слияние и разрешённую доставку. Владелец подключается к новому существенному решению, а не к каждому техническому этапу.

**«PR принят», «изменения в main» и «нужная версия работает» — разные состояния.** Завершённый выпуск требует проверки фактически запущенной версии и основного пользовательского сценария. Для библиотеки или другого продукта без сервера проверяется соответствующий опубликованный/переданный артефакт.

## Повседневные сообщения

| Что нужно | Куда писать | Достаточное сообщение |
| --- | --- | --- |
| Новая функция, пожелание к интерфейсу | Продукт | «Хочу, чтобы …» |
| Ошибка | Управление | «При действии … получаю …, ожидал …»; добавить пример/скриншот, если есть |
| Следующее готовое дело | Управление | «Продолжай следующую готовую задачу в рамках полномочий проекта» |
| Проверка после реализации | Управление | «Проверь PR …» |
| Статус | Управление | «Что уже подтверждено, что осталось и какое действие требуется от меня?» |
| Остановка | Управление и активная задача, если она выполняется отдельно | «Приостанови задачу … и сохрани состояние» |
| Сбой после выпуска | Управление | «После выпуска … перестало работать …; проведи диагностику» |

Если сообщение пришло не в тот чат, агент сам помогает перенести результат и даёт готовое поручение. Мне не нужно самостоятельно разбирать противоречащие технические отчёты.

## Продолжить в новом чате

При переполнении или замене чата использовать:

```text
Продолжаем продукт [ссылка на репозиторий]. Роль — management [или product].
Прочитай AGENTS.md, .ai-development/START.md и документы, указанные в .delivery/PROJECT.md.
Восстанови состояние по репозиторию, открытым PR и подтверждённому выпуску.
Продолжи текущую задачу в рамках уже выданных полномочий.
```

Не считать память чата доказательством актуального состояния. Для нового ревью при наличии доступа достаточно ссылки на PR; иначе управляющий готовит пакет для чата Claude. Для нового разработчика — ссылка на карточку задачи в доступном ему репозитории.

## Подключить существующий продукт

В управляющий чат передать:

```text
Подключи к [ссылка на репозиторий] стандарт https://github.com/sa713/ai-development.
Сначала прочитай существующие инструкции и состояние. Сохрани требования, историю,
незавершённые задачи и действующие разрешения. Настрой ссылки на существующие документы,
покажи и разреши противоречия. Подключение стандарта не разрешает функциональные изменения
или выпуск продукта.
```

Техническая процедура и обновления описаны в [guides/ADOPTION.md](guides/ADOPTION.md). Это работа управляющего; владельцу продукта не требуется выполнять Python-команды из руководства.

## Навыки и доступ

В комплект входят `ad-start-product`, `ad-manage-task`, `ad-review-change`. Они сокращают запуск процедур; стандарт полностью работает по сообщениям выше и без автоматического вызова навыка.

Подключение к конкретной среде: [guides/INTEGRATIONS.md](guides/INTEGRATIONS.md). Репозиторий приватный: каждый используемый инструмент должен иметь доступ. Установка в ChatGPT не устанавливает навыки в Claude или каждое окружение Codex автоматически. Открытие ссылки не выдаёт разрешений на запись.

Если агент не видит репозиторий или не умеет запускать другой инструмент, он прямо сообщает недостающую возможность и готовит минимальный ручной переход. Не обещает фоновую работу или автоматическую координацию, которых нет.

- [roles/product.md](roles/product.md), [roles/management.md](roles/management.md), [roles/developer.md](roles/developer.md), [roles/reviewer.md](roles/reviewer.md) — обязанности ролей.
- [guides/QUALITY.md](guides/QUALITY.md) — проверка и особенности разных продуктов.
- [guides/REVIEW_CHAT.md](guides/REVIEW_CHAT.md) — ручная передача в обычный чат Claude с телефона.
- [guides/RELEASE.md](guides/RELEASE.md) — выпуск, восстановление, сопровождение.
- [guides/ENVIRONMENTS.md](guides/ENVIRONMENTS.md) — подготовка работающей среды, CI, демонстрации и доставки; [templates/CI.yml](templates/CI.yml) — основа проверки PR.
- [guides/ADOPTION.md](guides/ADOPTION.md) — подключение и обновление стандарта.
- [guides/INTEGRATIONS.md](guides/INTEGRATIONS.md) — возможности и ограничения инструментов.
- [templates/PROJECT.md](templates/PROJECT.md) — паспорт продукта; остальные шаблоны используются по необходимости.
- [VALIDATION.md](VALIDATION.md) — выполненные проверки самого комплекта и границы подтверждения.
- [SOURCES.md](SOURCES.md) — основания решений и официальная документация.

Версия стандарта меняется контролируемо; история — [CHANGELOG.md](CHANGELOG.md). Новые правила добавляются по реальной необходимости. Объём документации и число агентов не являются показателями качества.
