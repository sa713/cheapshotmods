Не ломать обычное перемещение Tab и не перехватывать ввод в других полях. Длинный список прокручивается, меню учитывает границы экрана и не раздвигает страницу.

### 2. Единый порядок модов

Общий порядок:
1. тип, как в действующих фильтрах: **🅾️ → 💢 → 🌸 → 🧿 → raw-purple → raw-red → raw-green**;
2. уровень по убыванию;
3. основной параметр по убыванию;
4. при равном основном параметре — крит по убыванию, где он применим; неизвестный после известного, отдельно от нуля;
5. устойчивое разрешение полного равенства (существующий стабильный ID/ключ).

Сравнивать целые параметры/крит точно: Number и лексикографический порядок decimal TEXT не подходят для произвольных больших значений. Не путать сырьевые значения 6/7/8 с уровнем и цветом семейства. Технический tier сырья остаётся 0.

Применить правило к original/work, экипировке, выбору для одиночного/массового крафта и спискам вариантов модов. Не менять естественный порядок несвязанных меню, например возрастающих вариантов целевого уровня. Группировка одинаковых work, количества, надето и отдельное редактирование исходных строк сохраняются.

Упорядочивание выполняется **глобально до разбиения инвентаря на страницы**. Одной сортировки уже загруженных массивов недостаточно. Проверить cursor/limit/фильтры, загрузку следующих страниц, обновление после мутаций и использование общего порядка клиентом. В неизменном наборе нет пропусков/дубликатов; при изменении revision применяется согласованное обновление/сброс страниц. Не раскладывать большие количества поэкземплярно и не снимать ограничения запросов ради сортировки.

### 3. Два рецепта группового зелёного фьюза

Ограниченное исключение из TASK-007:
- **6 + 6 + 7 → 🅾️ 1.0, параметр 10**;
- **7 + 8 + 8 → 🅾️ 1.0, параметр 12**.

Входы только raw-green/tier 0 с указанными параметрами. Выход ordinary 🅾 без крита, не raw-red и не 🌸. Один результат стоит **28 алмазов**, n результатов — 28×n. Для этих рецептов нет выбора более высокого целевого уровня.

В существующем разделе массового крафта дать выбор одного из двух рецептов, автоматический preview и количество результатов. По умолчанию выбран весь максимум; пользователь может уменьшить число до 1. Не создавать тысячи options для количества. Сохранить прежний режим однородного массового фьюза.

Сервер считает запас **всего work владельца**, включая незагруженные страницы и партии/группы одного параметра, а не только присланные карточки:
- Nmax(6+6+7) = min(floor(Q6/2), Q7);
- Nmax(7+8+8) = min(Q7, floor(Q8/2)).

Q — свободные экземпляры. Существующее явное разрешение расходовать надетые добавляет их к Q; сначала расходуются свободные. При Nmax=0 показать, какого сырья не хватает, и запретить применение. Числа/количества/цена сохраняют BigInt/decimal TEXT без произвольного игрового потолка.

Preview показывает рецепт, выход, максимум, выбранное n, расход/остатки каждого входа и итоговую цену. Изменение рецепта/количества/includeWorn/revision/experiment обновляет preview; старый ответ не включает кнопку для нового выбора. После применения пересчитать оба рецепта из фактических остатков: Q7 общий, максимумы не означают возможность одновременно выполнить оба.

Новый запрос проверяется сервером: поддерживаемый рецепт, положительный целый count в пределах фактического максимума, owner из сессии, Origin/CSRF, experiment/revision и idempotency key. Не доверять клиентским output/cost/источникам. Не разрешать через новый DTO произвольные смешанные группы. Сохранить исторические legacy mixed receipts и точный retry их исходных payload; не ломать предварительную валидацию до чтения receipt.

Одно применение — одна транзакция, одна запись операции и одна отмена всего batch. Повтор той же команды возвращает receipt без второго расхода; KEY_REUSED/stale/чужой owner/недостаток/ошибка в середине не оставляют частичных изменений. Израсходованные надетые снимаются, output не надевается; undo возвращает состав, экипировку и расход. Изменяются только work/lots/history/расход: original, зафиксированный снимок и уровень игрока сохраняются.
