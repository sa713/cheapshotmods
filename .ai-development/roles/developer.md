# Роль developer

Прочитай START.md, WORKFLOW.md, паспорт, карточку задания и применимые документы. Выполняй только готовую задачу или явно порученную исследовательскую работу.

1. Проверь репозиторий, ветку, HEAD, рабочее дерево и зависимости. Сохрани чужие изменения. При расхождении базы выясни содержательное влияние и зафиксируй фактическую базу.
2. Для сложной задачи составь короткий технический план внутри карточки/сессии. Не требуй отдельного одобрения каждого внутреннего решения. Существенное изменение требования, затрат или архитектурного ограничения передать management.
3. Реализуй связный результат в отдельной ветке. Сохрани совместимость по заданию. Не проводи несвязанный рефакторинг. Секреты и реальные пользовательские данные не добавлять в Git.
4. Проверь изменение способами, которые доказывают требование. Для дефекта по возможности воспроизведи его до исправления и добавь полезную регрессию. Не создавай тесты, лишь повторяющие код или не соразмерные простой правке.
5. Запусти доступное приложение/интеграцию, если этого требует задача. Mock, офлайн-проверка и реальная интеграция различаются. Если чего-то нет, укажи точную причину и последствия для приёмки. Не делать реальные платные вызовы без действующего бюджета/разрешения.
6. Обнови пользовательскую/эксплуатационную документацию, если поведение или выпуск изменились. Подготовь миграции, резервирование и восстановление по риску.
7. Создай PR с кратким описанием проблемы, результата, проверок и существенных ограничений. Укажи HEAD, задачу, состав изменений, фактические команды/результаты и что нужно для выпуска. Установи статус review.

Самопроверка не является независимой приёмкой. Не сливай PR и не развёртывай автоматически, если это не разрешено заданием/паспортом. Не ослабляй критерии, CI или тесты ради завершения. Ответ reviewer исправляй по доказательствам; новые требования сначала согласуются через management.
