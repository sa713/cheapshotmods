## Техническая среда

- Выбрана техническая основа для подготовки: Node.js 24 LTS, TypeScript, Fastify 5, React, Vite, SQLite через `better-sqlite3`; один сервер приложения и один origin для UI/API. Конкретные совместимые версии и lock-файл проверяет и фиксирует TASK-001. Основания и ограничения — в TECHNICAL.
- Целевые способы доступа: мобильный браузер и Telegram WebView. Веб-интерфейс на русском. Основной маршрут владельца — с телефона.
- Установка, запуск, тесты, сборка, CI, миграции и контейнер подготовлены developer в TASK-001; команды — в RUNBOOK, фактические проверки конкретной версии — в карточке/PR. Полный интерфейс и живая интеграция остаются зависимой работой.
- Единая команда проверки: `bash scripts/verify.sh`. Обязательные jobs TASK-001: `verify` и `container-smoke`; их успешный запуск требуется подтвердить ссылками на реальные GitHub Actions runs. Наличие workflow не означает включённую branch protection.
- Тестовые пользователи и данные создаются изолированными фикстурами, без реальных аккаунтов/секретов Telegram. Подмена пользователя через публичный заголовок, query-параметр или production dev-login не разрешается.
- Preview/HTTPS-стенд, домен, production-сервер и канал предоставления секретов не назначены. Docker проверяется на локальном безопасном аналоге/CI; это не демонстрация реального Mini App.
- Для реального входа нужны выделенный бот, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OIDC_CLIENT_ID`, `TELEGRAM_OIDC_CLIENT_SECRET`, регистрация разрешённых origin/callback URL и Mini App URL у BotFather. `PUBLIC_BASE_URL`, `DATABASE_PATH`, серверный секрет сессий и версия сборки конфигурируются отдельно. Значения секретов в GitHub/чат не помещать.
- Новая внешняя инфраструктура, платные API и бюджет не согласованы. Ресурсы других продуктов владельца сюда не переносятся. Планировочная цель — один небольшой Linux-хост с постоянным диском; фактическую память, объём и задержки измерить в TASK-001, назначение хоста решается до живого стенда.

## Полномочия

Основание: поручение владельца от 2026-11-05 — подключить стандарт, прочитать требования, проверить реализуемость, подготовить следующую задачу и вести состояние в репозитории. PRODUCT.md разрешает обычные решения внутри согласованных требований. Это не поручение management реализовать всё приложение в текущем чате.

| Действие | Действующее правило |
| --- | --- |
| Документы, техническая подготовка и PR | Разрешены в пределах поручения; отдельная рабочая ветка |
| Реализация developer | Управляющий готовит задание и готовое поручение здесь; реализацию выполняет Codex в отдельной сессии. Внутренние агенты управляющего не подменяют этот этап |
| Слияние в main | Не делегировано текущим поручением; подготовительный PR не считать объединённым |
| Публикация, стенд и production | Подготовка конфигурации/локальных артефактов разрешена; внешнее размещение и изменение рабочих систем не разрешены |
| Рабочие данные и ресурсы других проектов | Не использовать; только изолированные тестовые данные |
| Платные API и новые расходы | Не разрешены |
| Создание/изменение бота, BotFather, рассылки | Не поручены; сообщать владельцу только конкретный недоступный шаг после подготовки конфигурации |
| Продуктовое принятие | Владелец; технические эксперименты TASK-001 проверяются по карточке, пользовательский полный продукт ими не принимается |
| Независимая проверка | Отдельный reviewer/сессия; management готовит пакет для ручного чата Claude и организует исполнение проверок |
| Параллельные реализации | Одна активная реализация на репозиторий |

## Подтверждённые возможности и ограничения

- Work management: 2026-11-05 подтверждены чтение приватного репозитория через GitHub-интеграцию, разрешения push/PR и локальные Node.js 24.22.1, npm 11.9.0, Python 3.12.14. Успех записи в GitHub подтверждается сохранённым коммитом и PR; наличие прав само по себе им не является.
- В Work доступны команды, GitHub-интеграция и внутренние агенты. Management ошибочно использовал внутренних исполнителей для F1–F6 и повторной проверки 2026-11-05, приняв слова владельца о постановке заданий здесь за смену процесса. Это отклонение от согласованного маршрута, а не разрешение на его дальнейшее использование. Фактические код/коммиты/запуски сохраняются в истории. Docker/gh в той среде не обнаружены; доступ к прежней сессии Codex Cloud не подтверждён.
- В сессии developer TASK-001 подтверждены отдельный cloud checkout, чистая исходная ветка, Node 24.22.1/npm 11.9.0, сеть через proxy, Docker 29.9.2, Chromium/Playwright. Сетевым командам и Docker socket требуются разрешения sandbox; исходные инструменты Work и эта среда — разные среды. Результаты и ограничения конкретной версии сохраняются в карточке.
- Действующий маршрут по уточнению владельца от 2026-11-06: этот чат — management. Здесь обсуждаются и оцениваются требования/отзывы, сохраняются решения, готовятся задания и готовые поручения для Codex, организуется приёмка. Код реализуется в отдельной сессии Codex по этому поручению. Формулировка «задачи ставишь здесь» не разрешает management писать код или заменять Codex внутренними исполнителями. Предыдущая трактовка от 2026-11-05 была ошибочной. Автоматический запуск прежней сессии Codex Cloud, Claude и фоновое продолжение не настроены.
- Доступ Claude к приватному репозиторию не подтверждён. Применяется готовый текст и один читаемый пакет материалов с телефона; обязательные тесты исполняются в отдельной доступной среде.
- Подключение пакета выполнено через GitHub-интеграцию по одному SHA по разделу ADOPTION о работе без checkout источника. Проверены Git blob SHA всех 33 исходных файлов, сформированы 45 управляемых копий и SHA-256 manifest. Официальный `adopt.py --apply` не запускался: это проверенное воспроизведение его плана, а не отчёт о запуске скрипта.
- Конфликтов с существующими AGENTS.md/CLAUDE.md нет: до подключения в репозитории был только PRODUCT.md. Не создан дублирующий `.delivery/PRODUCT.md`; паспорт указывает существующий источник.
