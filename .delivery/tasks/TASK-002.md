## Объём и критерии приёмки

### A. Полный мобильный интерфейс

Реализовать в существующем React-приложении:
- вход, выход, корректное обнаружение Mini App, загрузку/восстановление сессии и понятные ошибки;
- уровень игрока, точные итоговые урон/здоровье и счётчик надетых модов из 100;
- исходный инвентарь: группы модов всех четырёх типов, уровни 1.0–6.0, фактический параметр и количество, добавление/правку/удаление, чтение больших наборов страницами;
- один текущий эксперимент: рабочий инвентарь, выбор экземпляров для крафта, preview результата/цены и применение;
- экипировку/снятие с правильным учётом доступных экземпляров;
- цену операций, общий расход алмазов, повторную отмену последнего крафта и подтверждаемый сброс;
- состояния сохранения, повтор после неопределённого сетевого исхода и загрузку актуальных данных при конфликте.

Русский интерфейс, удобный для касаний и экранной клавиатуры. На ширинах 360 и 390 px нет горизонтальной прокрутки, скрытых основных действий и перекрытия управления. Длинные точные числа остаются читаемыми. Рабочие экраны обязательны: надпись «интерфейс готовится» не соответствует результату.

### B. Сквозные пользовательские проверки

На настоящем сервере/SQLite в изолированной среде пройти S-01–S-06 через UI браузера. Использовать подписанные тестовые Telegram-данные и тестовые адаптеры транспорта только в тестовой оснастке. Не добавлять в production test-login, фиксированного игрока, доверенный заголовок, seed endpoint или отключение проверки подписи. Подмена транспорта провайдера в тестах не считается живым Telegram.

Обязательные примеры:
- уровень 200 и 🅾10/💢8/🧿8 → урон252, здоровье200; уровень101 с одним 💢8 →110, с двумя →118;
- инвентарь больше100 модов хранится; надевание101-го отклоняется без изменений; 100 🅾10 при уровне200 → урон2200;
- шесть 🅾1.0 по10: один крафт → три исходных плюс один 🅾2.0 по15, расход84; второй →168; последовательные отмены →84 и0. Исходный инвентарь не меняется;
- 10/11/12 →17, 15/15/15 →23; все уровни/четыре типа/20 цен сохранены, 💚3.0=162;
- крафт надетых экземпляров, надевание результата и отмена восстанавливают нужную экипировку; текущий уровень игрока сохраняется;
- правка исходного набора не меняет начатый эксперимент; сброс берёт актуальный исходный набор и очищает экипировку/историю/расход;
- два игрока изолированы; один Telegram ID в обоих тестовых способах входа получает одни данные;
- reload/новый вход/перезапуск контейнера сохраняют инвентарь, экипировку, историю и возможность отмены;
- потеря ответа после commit не удваивает крафт/расход; конфликт ревизий не затирает данные; ошибка сохранения не отображается как успех.

Игровые числа передаются точно, без округления через Number. Проверить большой integer и производный параметр после крафта через UI/API/сохранение. Не превращать размер страницы или технический лимит запроса в предел игрового инвентаря.

Завершить клиентскую и серверную связку обоих входов. Сохранить PKCE/state/nonce, проверку подписи/issuer/audience/времени, серверную сессию, Origin/CSRF и связь по подтверждённому Telegram ID. Обосновать выбранные обычные параметры; не ослаблять сохранность и защиту ради тестов.

Без секретов контейнер запускается, сообщает о ненастроенном входе и не открывает личные API. В окружении изолированных тестов весь калькулятор проверяется без настоящего бота.
