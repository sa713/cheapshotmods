# TASK-000 — название результата

- Статус: draft
- Риск: низкий / обычный / повышенный — причина
- Требование/решение владельца: ссылка
- Репозиторий, базовая ветка и исходный полный SHA: заполнить до ready
- Зависимости и конфликтующие работы: нет либо ссылки
- PR: ссылка после создания; текущие ветку/HEAD, CI и слияние получать из GitHub

## Цель и границы

Наблюдаемый результат, что входит и что не входит. Существенные ограничения, технические решения и область разрешённых изменений.

## Критерии приёмки

Для каждого критерия: исходные условия/пример → действие → ожидаемый результат → способ проверки. Включить важные ошибки и ограничения. Не подменять пользовательский результат перечнем файлов.

## Проверка и доставка

Целевые команды/сценарии, интеграции, тестовые данные, допустимые реальные вызовы и расходы. Нужны ли миграция, пользовательская демонстрация и выпуск; при not_applicable указать основание. Ссылка на runbook.

## Полномочия

Ссылка на паспорт и дополнительные решения по этой задаче. Указать самостоятельность developer, полномочия на merge/release и действующий бюджет. Пустое поле не расширяет права.

## Передача и результаты

Выполненные критерии, команды/результаты, непроверенное и причина, отчёт reviewer с HEAD, следующий шаг и ответственный. При новой сессии восстанавливать состояние отсюда и по фактам репозитория.

- product_acceptance: pending / accepted / delegated / not_applicable
- Слияние: по связанному PR; если неприменимо — причина. Результат интеграции указывается в доказательстве проверки/выпуска
- delivery: pending / verified / failed / not_applicable — версия/доказательство
- Последнее подтверждение: дата и источник
