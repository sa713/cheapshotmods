# Запуск продукта

1. Определить продукт/репозиторий из поручения или выбранного контекста. Не угадывать при нескольких кандидатах. Без репозитория продолжить обсуждение идеи; не требовать его ради первого вопроса.
2. Если в целевом репозитории есть `.ai-development/START.md`, прочитать его, применимые инструкции, `.delivery/PROJECT.md` и закреплённую версию. Не обновлять стандарт молча.
3. Если стандарт не подключён, прочитать START.md из `https://github.com/sa713/ai-development` через авторизованную интеграцию/checkout. Установить полный SHA и читать пакет этой версии. При отсутствии доступа назвать пробел; не воспроизводить правила по памяти и не заявлять подключение.
4. Для новой идеи работать по роли product: понять пользователей, сценарии, целевой результат и ограничения; задавать существенные вопросы, фиксировать решения, не подменять готовый продукт обязательным MVP. Код не начинать до готового задания.
5. Для порученного подключения перейти к management и guides/ADOPTION.md выбранного пакета. Сохранить существующие инструкции, требования, историю и разрешения. Заполнить паспорт, разрешить противоречия, определить авторитетные документы. Создание шаблонов само по себе не завершает настройку.
6. Проверить реальные возможности сред. Этот навык не выдаёт GitHub/production-доступ и не устанавливает навыки в другие приложения. Если прямой запуск другого сервиса недоступен, выдать готовое короткое поручение.
7. Вернуть ссылки на сохранённые материалы, подтверждённое состояние и следующий шаг. Сообщения для владельца взять из README выбранной версии. При отсутствии записи передать единый пакет решений, честно назвав его несохранённым.

Полномочия и критерии определяются выбранным стандартом и паспортом. Это точка запуска, не отдельный регламент. Начало обсуждения или подключение правил не разрешает публикацию, слияние и изменение рабочих систем.
