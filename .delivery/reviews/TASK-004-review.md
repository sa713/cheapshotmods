## Смысл исправления и проверенные инварианты

Прежде каждый craft создавал новый output UUID и undo удалял всю output row. Простое объединение карточек без изменения undo могло потерять другие экземпляры. Теперь Store добавляет ровно1 к work stack по owner/kind/tier/value, а history.output остаётся delta quantity1. Undo вычитает1, возвращает три входа, pre-craft equipment и стоимость; текущий level сохраняется. Partial unique index действует только при `scope='work'`, original rows/IDs/ADD/absolute EDIT/delete semantics сохраняются.

До started source-правки меняют вклад в work по старым/новым attrs и quantity, а не по original ID. Если original ID занят другим оставшимся work tuple, новый stack получает свободный UUID. После started source-правки не меняют experiment; reset агрегирует актуальные original batches через BigInt и очищает history/equipment/spent. Work ID не обязан совпадать с ID отдельной исходной записи.

Schema3 migration выполняется одной IMMEDIATE transaction. Она собирает work descriptors из current и всех retained consumed/output, выбирает canonical IDs с приоритетом active row, объединяет BigInt quantities и remaps history/player equipment. Original scope не участвует в work identity map: одинаковый ID может законно иметь разные attrs в original и work. Обратная проверка всех undo шагов подтверждает доступность output/consumed/equipment и spent; malformed/missing/conflicting refs дают безопасный `INCONSISTENT_MOD_HISTORY`, без частичных changes/index/version. History читается/обновляется ограниченными100row batches, seq использует safeIntegers/BigInt. Schema3 reopen не повторяет migration.

Сохранённые commands payload/result/created не переписываются. Exact replay остаётся до revision check и возвращает прежний receipt без новой мутации; UI после ответа перечитывает текущие state/inventory. Новый key со старой revision конфликтует. Migration повышает revision каждого существующего player ровно на1; owner/level/experiment/started/spent и history seq/price сохраняются. Derived129digit work totals допустимы, исходные128digit записи остаются редактируемыми.
