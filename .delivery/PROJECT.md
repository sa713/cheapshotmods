## Техническая среда

- Выбрана техническая основа для подготовки: Node.js 24 LTS, TypeScript, Fastify 5, React, Vite, SQLite через `better-sqlite3`; один сервер приложения и один origin для UI/API. Конкретные совместимые версии и lock-файл проверяет и фиксирует TASK-001. Основания и ограничения — в TECHNICAL.
- Целевые способы доступа: мобильный браузер и Telegram WebView. Веб-интерфейс на русском. Основной маршрут владельца — с телефона.
- Решение владельца от 2026-11-06: установка на его существующий Debian, доступ без домена — по IP и порту. Конкретный публичный IP, порт, версия ОС и доступные ресурсы ещё не переданы. Перед установкой нужен read-only preflight и проверка существующего proxy/занятых портов.
- Техническая основа принята в TASK-001. Полный интерфейс, эксплуатационные защиты и комплект Debian реализуются/принимаются в TASK-002; команды — в RUNBOOK, фактические проверки конкретной версии — в карточке/PR. Живая интеграция проверяется после операторской установки.
- Единая команда проверки: `bash scripts/verify.sh`. Обязательные jobs TASK-001: `verify` и `container-smoke`; их успешный запуск требуется подтвердить ссылками на реальные GitHub Actions runs. Наличие workflow не означает включённую branch protection.
- Тестовые пользователи и данные создаются изолированными фикстурами, без реальных аккаунтов/секретов Telegram. Подмена пользователя через публичный заголовок, query-параметр или production dev-login не разрешается.
- Preview/HTTPS-стенд, домен, production-сервер и канал предоставления секретов не назначены. По решению владельца они настраиваются после передачи полного кандидата TASK-002 и не блокируют независимую разработку/изолированную проверку. Docker проверяется на локальном безопасном аналоге/CI; это не демонстрация реального Mini App.
- Для реального входа нужны выделенный бот, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OIDC_CLIENT_ID`, `TELEGRAM_OIDC_CLIENT_SECRET`, регистрация разрешённых origin/callback URL и Mini App URL у BotFather. `PUBLIC_BASE_URL`, `DATABASE_PATH`, серверный секрет сессий и версия сборки конфигурируются отдельно. Значения секретов в GitHub/чат не помещать.
- Новая внешняя инфраструктура, платные API и бюджет не согласованы. Ресурсы других продуктов владельца сюда не переносятся. Планировочная цель — один небольшой Linux-хост с постоянным диском; фактическую память, объём и задержки измерить в TASK-001, назначение хоста решается до живого стенда.

## Размещение без домена — решение владельца 2026-11-06

Домен или поддомен не использовать; пользователь выбрал адрес вида IP:порт на своём Debian. Протокол доступа для сохранения Telegram-функций должен быть HTTPS. Конкретный публичный IP и порт ещё неизвестны; формат рабочей цели — `https://IP:порт`.

Проверенные ограничения и источники:
- Telegram [WebAppInfo](https://core.telegram.org/bots/api#webappinfo) требует HTTPS URL. [Telegram Login](https://core.telegram.org/bots/telegram-login) обрабатывает только заранее зарегистрированные Allowed URLs. Приём именно числового IP с выбранным портом в BotFather ещё не проверен; не заявлять его подтверждённым.
- [Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability) выпускает публично доверенные сертификаты на IPv4/IPv6; IP-сертификаты shortlived, 160 часов. Поэтому отсутствие домена само по себе не означает невозможность HTTPS. Нужны реальная доступность проверки адреса и автоматическое обновление сертификата.
- [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https) по умолчанию использует собственный CA для IP. Принятый комплект содержит обычный Caddyfile, без отдельно проверенной настройки публичного IP-сертификата/его продления. Нельзя обещать, что достаточно заменить доменное имя числовым IP и получить доверенный HTTPS для телефона/Telegram.

Следующий шаг: получить IP и диагностический вывод выбранного хоста, определить свободный порт и доступную схему выдачи/обновления сертификата, затем проверить регистрацию точного IP-origin/callback в Telegram. Не отключать HTTPS, Secure cookies или проверку Telegram ради доступа по HTTP. Исходный runtime-кандидат остаётся принятым в своей области; выбранная внешняя конфигурация по IP пока не проверена.
