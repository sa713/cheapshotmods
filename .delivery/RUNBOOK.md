## Что обязан подготовить TASK-001

1. `npm ci`, `npm run dev`, `npm run build`, `npm start`; exact Node/npm и версии зависимостей закреплены, `.env.example` содержит только имена/безопасные примеры. До реализации эти команды не заявлять работающими.
2. `bash scripts/verify.sh`: чистая установка из lock-файла, типы, lint, содержательные unit/integration tests и production build. Отдельно документировать smoke контейнера и запуск тестов браузера. В реальном GitHub CI обязательны `verify` и `container-smoke`.
3. Тестовые данные создаются в отдельной временной БД. Проверки не читают секреты и рабочие данные. Без конфигурации Telegram приложение показывает честное состояние недоступного входа, личные API требуют сессию.
4. `/health` и `/version`: версия сборки равна полному Git SHA, health отражает готовность хранилища без вывода личных данных/секретов.
5. Версионируемый Docker-образ, локальный compose с постоянным volume, миграция чистой БД и сохранение данных при перезапуске. Сборка/запуск контейнера реально выполняются в доступной CI-среде; отсутствие Docker локально у management не заменяет этот результат.
6. Проверенный backup/restore на тестовой БД. Для WAL использовать согласованный SQLite backup API/операцию с остановленной записью, не копию только основного файла во время записи. Восстанавливать в новый volume и сравнить исходный набор, эксперимент, экипировку, историю, расход и ревизию.
7. Сохранить команды, наблюдения и точную версию в карточке TASK-001. Объяснить все skipped/незапущенные проверки. Проверить, что намеренно ошибочный контрольный расчёт в временной копии даёт красный verify; не коммитить испорченную проверку.

## Живая интеграция и выпуск

До назначения хоста нет команды production-выпуска и адреса preview. Для живой проверки требуются бот, зарегистрированный HTTPS origin/callback/Mini App URL, безопасно предоставленные секреты и разрешение использовать целевое окружение. План и ограничения — [TECHNICAL.md](TECHNICAL.md).

Перед первым живым стендом management дополняет этот документ точными командами, адресами, местом данных, действиями в BotFather, проверкой версии и восстановления. Владельцу передаётся один подготовленный шаг, который недоступен агентам, а не список ручной настройки всего проекта.

Для полного пользовательского принятия открыть сервис с телефона, войти одним Telegram-пользователем в браузере и Mini App, проверить общий эксперимент, затем войти вторым пользователем и убедиться в изоляции. Выполнить крафт, потерю ответа/повтор, конфликт, отмену и сброс по S-01–S-06. Только локальные фикстуры не подтверждают эти результаты.
